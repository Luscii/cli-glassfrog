## Phase 1: The feature-gate recognizer [Shared]

- [ ] **T001** [Shared] Add the feature-gate recognizer — `Gate` type + static gated-operation registry + path-template matcher + `RecognizeFeatureGate` — in a new `internal/apiclient/featuregate.go`, with RED-first table-driven unit tests
  - **Scope**: In a **new** file `internal/apiclient/featuregate.go` (sibling to `problem.go` — recognition is API-response interpretation, the same domain as `ExtractProblem`), add: (1) a code-free `Gate` enum — `GateNone`, `GatePremiumAsyncProposals`, `GateAIIntegration` — modeling the gate **kinds** the spec carries (plan ADR-3); (2) a **static** gated-operation registry as a slice of `{method, pathTemplate, gate}` rows transcribing the spec's gate metadata, holding **only** the four reachable Premium async-proposal writes: `POST /proposals`, `POST /proposals/{proposal_id}/propose`, `POST /proposals/{proposal_id}/withdraw`, `POST /proposals/{proposal_id}/responses`, each `GatePremiumAsyncProposals` (the `withdraw`/`responses` commands need not exist yet — recognition keys on the operation, not the command); (3) a small path-template matcher comparing method then path **segment-wise**, where a `{…}` template segment matches any one concrete segment, literal segments must match exactly, segment counts must be equal, and the query string is ignored; (4) `RecognizeFeatureGate(method, path string, status int) Gate` — **pure and total** (no I/O, never reads the token, never panics, never returns an error): it returns the registered gate when `status == 403` **and** the operation matches a registered row, and `GateNone` otherwise (a non-403 status from a gated op, or any status from an unregistered op, returns `GateNone`). Document on the function and the `Gate` type that a non-`None` result is a **suspicion** — the 403 is *consistent with* a known plan gate, never a confirmed plan limit — because the 403 body is not self-identifying (plan ADR-4; spec Non-Behaviors). Add **no** wiring into `reportFailure`/`Diagnose`, **no** error-chain change, **no** new `Outcome`/`ExitCode`. RED-first unit tests in `featuregate_test.go`.
  - **Acceptance criteria**:
    - `RecognizeFeatureGate("POST", "/proposals", 403)` returns `GatePremiumAsyncProposals`; likewise for concrete `/proposals/prp_0123/propose`, `/proposals/prp_0123/withdraw`, and `/proposals/prp_0123/responses` (the `{proposal_id}` segment matches the concrete id)
    - A non-403 status on a gated operation returns `GateNone` — covered for `422`, `412`, and `200` on `POST /proposals`
    - A non-gated operation on a `403` returns `GateNone` — covered for `GET /roles/role_0123` and a `POST` to an unrelated path (e.g. `/tensions`)
    - Path-template matching is exact on shape: a segment-count mismatch does not match (`/proposals/a/b/propose` ≠ `/proposals/{proposal_id}/propose`), a literal segment must match (`/proposals/{id}/withdraw` does not match `/proposals/x/propose`), and a trailing query string is ignored
    - `GateAIIntegration` exists in the `Gate` type, but a guard test asserts **no registry row** carries it today (the modeled-but-unregistered boundary, plan ADR-3); a registry change-detector asserts the registry holds exactly the expected set of gated rows — the expected row count AND each expected `(method, path-template, gate)` row present — so a dropped row or a zero-valued (`GateNone`) gate fails loudly (the registry is a slice; if the test indexes it by building a map, pair a length check with a comma-ok lookup — the map-zero-value trap, LEARNINGS)
    - `RecognizeFeatureGate` is pure/total: no network, no filesystem, no token access, no panic, no returned error; an unknown/malformed `method`/`path`/`status` yields `GateNone`
    - A non-`None` `Gate` is documented as a possible/suspected gate, never a certain one; `go build ./...` and `go vet ./...` are clean and all tests run offline
  - **Dependencies**: None (the base carries 015 `ProblemError`/`ExtractProblem` and the `internal/apiclient` package from `main`; the recognizer needs only the standard library)
  - **Plan reference**: Phase 1 (the recognizer); ADR-1 (standalone, unwired pure capability — no `Diagnose`/`reportFailure` wiring, no error-chain change), ADR-2 (key on HTTP method + path template matched against a static per-operation registry), ADR-3 (model both gate kinds, register only the reachable Premium family; `GateAIIntegration` modeled-but-unregistered), ADR-4 (possibility, not certainty)
  - **Scenario references**: feature-gate-recognition.feature: "A 403 from advancing a draft is recognized as a possible plan limit", "A 403 from creating a proposal is recognized as a possible plan limit", "A 403 from recording a response is recognized as a possible plan limit", "A 403 from a non-gated operation is not recognized as a plan limit", "A non-403 failure from a gated operation is not recognized as a plan limit", "Recognition keys on the operation and status, not the response body", "A permission denial on a gated operation is flagged as possible, not confirmed", "The ai_integration gate is modeled but no operation triggers it today"
  - **Risk**: ⚠️ Register **explicit per-operation rows**, never a `POST /proposals*` prefix rule — a future non-gated `POST` under `/proposals` must not mis-recognize (plan ADR-2). ⚠️ The matcher must require equal segment counts and ignore the query string; pin the edge cases (segment-count mismatch, literal-vs-wildcard, trailing slash, query) with tests. ⚠️ Keep `GateAIIntegration` in the type but **out** of the registry, guarded by an assertion test so the boundary can't drift silently (plan ADR-3). ⚠️ The registry change-detector must catch a dropped row or a zero-valued (`GateNone`) gate — assert the expected row count plus each expected row's presence (the registry is a slice); the comma-ok + length-guard form applies only if the test builds a map from it (the map-zero-value trap, LEARNINGS). ⚠️ Do **not** wire the recognizer into `reportFailure`/`Diagnose` or alter any error type — that is #61; keep #60 a pure leaf (spec Non-Behaviors). ⚠️ Read only `method`/`path`/`status` — never the token or the response body (CONSTITUTION II; spec Non-Behavior on body-independence).
