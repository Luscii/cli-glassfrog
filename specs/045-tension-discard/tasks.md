- [ ] **T002** [Shared] Add the `tension discard <ten-id>` command — `newTensionDiscardCommand` + `runTensionDiscard` (bodyless `DELETE`, 404-as-success interception, synthesized result, `204`-vs-`404` stderr advisory) + wiring under 042's `tension` group — RED-first unit tests for every branch
  - **Scope**: In `internal/cli/tension.go` (beside `runTensionUpdate`), add `newTensionDiscardCommand(seam tensionSeam) *cobra.Command`: a guard-registered leaf (`Use:"discard <ten-id>"`, `Args: cobra.ExactArgs(1)`, non-empty `Short`, `SilenceErrors`/`SilenceUsage`) declaring **no editable-field flags**; it reads the persistent `--base-url`/`--output` and their `Changed()` presence into a `tensionDiscardConfig`, then delegates to pure `runTensionDiscard`. **Reuse 042's existing `tensionSeam`** (no new seam). `runTensionDiscard(cfg) (Outcome, error)` follows the sibling shape (035-widened): (1) `resolveRenderTarget(cfg.seam, cfg.outputFlag, cfg.outputPresent, cfg.stderr)` FIRST (a bad `--output` is a fail-fast `UsageError(2)` with no request — there are no input-field checks); (2) `assemble` → `newClient` → `NewRetryExecutor`; (3) send **one** `Execute` to `DELETE /tensions/{id}` with **`out == nil`, no body, and no `Content-Type`** (`url.PathEscape` the id, passed through unvalidated — plan ADR-1). Then **interpret the outcome** (plan ADR-2/ADR-4): if `err == nil` (a `204`), it is a success — note "discarded"; else if `errors.As(err, &respErr)` with `respErr.StatusCode == http.StatusNotFound`, fold it into success — note "already gone"; **otherwise** route to `reportFailure(cfg.stdout, cfg.stderr, rt.format, err)`. On either success branch: write the one-line advisory to `cfg.stderr` (discarded vs already-discarded), build the synthesized result `{data:{id,discarded}}` from `cfg.id`, and render it on stdout exactly as the siblings do — machine format → marshal to `json.RawMessage` + `output.RenderSuccess`; human/`-o template` → `writeHuman(cfg.stdout, cfg.stderr, rt.tmpl, render.ResourceTensionDiscard, rt.format, render.TensionDiscardView{ID: cfg.id})` (buffer-then-write; a render failure → `RuntimeError(1)`); return `Success`. Attach the leaf to 042's group by extending `newTensionCommand` to `MustRegister` it, and widen the group `Short` to name discard. Never read `ctx.Cred.Token`; add no new `Outcome`/`ExitCode`.
  - **Acceptance criteria**:
    - `glassfrog tension discard ten_0123` issues one bodyless `DELETE /tensions/ten_0123` (no `Content-Type`, `out == nil`); on `204` it prints the synthesized result, writes a "discarded" advisory to stderr, and exits 0
    - A `404` response is treated as success: identical synthesized result on stdout, an "already discarded — nothing to do" advisory on stderr, **no not-found error**, exit 0 — and the interception keys on `StatusCode == 404` only
    - `-o json` emits `{"data":{"id":"ten_0123…","discarded":true}}` verbatim; `full`/`compact`/`-o <template-ref>` render the human confirmation line — identical for `204` and `404`
    - Missing `<ten-id>` or more than one positional → cobra `UsageError(2)`, **no request** (transport tripwire); a stray field flag (`--body`/`--status`/…) is a cobra unknown-flag `UsageError(2)`
    - A present-but-invalid `--output` → `UsageError(2)`, **no request** (transport tripwire)
    - `*AuthError{NoCredentials}` → UsageError(2); `*AuthError{CredentialError}` → RuntimeError(1); `*TransportError` → NetworkUnavailable(6); `401`/`403` → PermissionError(4); `429` → RateLimited(5) and the `DELETE` is **not** auto-retried; other non-2xx → APIError(3) — all via `reportFailure` (404 alone diverted to success)
    - No new `Outcome`/`ExitCode`/root flag; `create`/`list`/`get`/`update` unchanged; no token in any output; all branches run offline; `go build`/`go vet` clean
