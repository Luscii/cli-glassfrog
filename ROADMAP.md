# Glassfrog CLI — Roadmap

This roadmap sequences the problems in `ISSUE-TREE.md`. Its spine is VISION success criterion #2 — *an AI agent completes a real task end-to-end, reading a practitioner's roles and submitting a valid proposal, without the human needing any knowledge of the API* — front-loaded by the prerequisite that the CLI must exist at all. The read half of that spine has landed: the foundation runs and authenticates, the self-service and governance reads have shipped (org tree still following), cross-model search is done, and the actor-governance reads have landed in both directions. The write half has landed too — tension capture, the optimistic-concurrency guard that protects governance writes, and the proposal write path itself. The agent operating surface that packages how an agent drives the CLI has also shipped, and is being picked up again.

Two things then reshaped the frontier. The write path's **first live exercise** produced a cluster of fidelity problems — not missing endpoints, but gaps between what the server did and what the operator was told, and knowledge the assembler needs that nothing carried. And **refreshing the vendored contract** showed the published API had moved underneath the plan: the numeric identifier the write path needs is now readable on role reads through a declared transition-only parameter, the change-set grammar is published rather than folklore, and surfaces the CLI does not yet reach appeared ahead of the web app — which widened PROJECT.md's scope to admit agents and skills, role context, and channels. So Now is about write-path **fidelity** rather than write-path existence, extended by two reads whose absence is a divergence from what the API already offers. Next carries the settings refactor, the operating surface being picked up again, the drift check the contract update argued for, and the first of the newly-admitted areas. Later holds the narrowest write-path gap, a Maintainer-facing enhancement, and the newly-admitted areas whose need is gated or anticipated rather than felt. Sequence is order, not schedule.

Two VISION boundaries bear on the sequenced problems, recorded here so they are weighed when each is committed rather than rediscovered. Exclusion 2 (*no local governance logic*) permits a change-set grammar reference that **informs** an assembler but not one that pre-rejects a change set locally — the server stays the judge of what is valid. Exclusion 4 (*no data store or sync engine*) and the live-stateless constraint bear on retaining learned identifier resolutions; the refreshed contract answers part of that for roles, leaving the accountability and domain residue where the tension still applies.

The three organizational parent areas — *Project Foundation*, *Client Foundation*, and *Endpoint Commands* — contribute the child problems sequenced below rather than being sequenced themselves. A fourth root problem, *Unequipped Agent Operators* (the agent operating surface), is sequenced directly and contributes children of its own.

## Now

The landed foundation and client-hardening, the broad read surface, the output and pipeline legibility work still in the pipeline, the write path whose fidelity is the live frontier, and two reads whose absence diverges from what the API already serves.

1. **No Runnable CLI** *(Project Foundation)* — nothing can be built or run until the CLI exists as a runnable skeleton with a command framework; hard prerequisite for every other problem. (addressed)
2. **Unauthenticated Access** *(Client Foundation)* — every command depends on a proven org + person identity; without it nothing reaches the API. (addressed)
3. **Undefined Connection Settings** *(Client Foundation)* — the CLI must know which token, organization, and base URL to use before any call; credential discovery/storage and connection resolution have both landed. (addressed)
4. **Self-Service Reads** *(Endpoint Commands)* — the smallest real vertical slice (`/me`, my roles, my actions, my projects); all four have shipped end-to-end. (addressed)
5. **Silent Truncation** *(Client Foundation)* — pagination is load-bearing once reads return large sets or the org tree (CONSTITUTION VI); the pagination spec has landed. (addressed)
6. **Getting Throttled** *(Client Foundation)* — rate-limit handling matters as read volume grows (CONSTITUTION X); the rate-limit spec has landed. (addressed)
7. **Runtime-Dependent Distribution** *(Project Foundation)* — ship the CLI as a standalone, dependency-free executable (CONSTITUTION XII); the self-contained build and install script have landed (Homebrew tap and npm wrapper channels still in flight). (addressed)
8. **Opaque Failures** *(Client Foundation)* — fail legibly with a cause and a next step (CONSTITUTION II + III); error extraction, diagnostic normalization, and output-aware failure rendering have all landed. (addressed)
9. **Unconsumable Output** *(Client Foundation)* — make output agent-parseable and human-readable (VISION principle 3); structured serialization, format selection, and user-defined templates have landed, with templated human rendering following. (in score)
10. **No Automated Pipeline** *(Project Foundation)* — a CI quality gate (lint + tests) plus release drafting that guards every change before it reaches main; release drafting, PR administration, and main-branch verification have landed, with PR validation following. Clusters with *Runtime-Dependent Distribution* (drafting the version ↔ building and publishing the binary). (in score)
11. **Governance Reads** *(Endpoint Commands)* — the full read surface (roles, circles, accountabilities, domains, policies, projects); role, domain, policy, and project reads have landed, with the organization tree following. (in score)
12. **Tension Capture** *(Endpoint Commands)* — where the write half of VISION success #2 begins; capture, reads, discard, and subrole roll-up have landed, with tension update following. (in score)
13. **Actors Disconnected from Governance** *(Endpoint Commands)* — read the actor↔governance link in both directions: who fills a role (whom to contact) and an actor's governance footprint (roles, accountabilities, domains, purposes); role-fillers, the actor read + assignments, and subrole filler roll-up have all landed. Relates to *Tension Capture*. (addressed)
14. **Who to Contact for a Role** *(Endpoint Commands)* — given a role relevant to a tension, resolve which actor fills it so the operator knows whom to reach out to; the role-fillers read and its subrole roll-up have landed. Clusters with its parent above. (addressed)
15. **An Actor's Governance Footprint** *(Endpoint Commands)* — given an actor, surface the roles they fill and the accountabilities, domains, and purposes those carry; the actor read and assignments have landed. Clusters with its parent above. (addressed)
16. **Clobbered Changes** *(Client Foundation)* — optimistic concurrency for governance writes; version capture on read, guarded writes (`If-Match`), and stale-write (`412`) surfacing have all landed. Lands ahead of the *Proposal Write-Flow* it protects. (addressed)
17. **Proposal Write-Flow** *(Endpoint Commands)* — the multi-step governance write path (create → propose → respond → accepted); the largest feature and the frontier of VISION success #2, modeled as the **Governance Proposals** solution (creation / reads / advance / withdraw / respond, `changes[]` pass-through) — all five legs have landed. Its first live exercise is what surfaced the fidelity problems below. (addressed)
18. **Unsignalled Plan Limits** *(Client Foundation)* — surface a clear "not available on your plan" signal for Premium / `ai_integration` endpoints (403); the plan-gating signal the proposal write path needs (pairs with *Proposal Write-Flow*), modeled as the **Plan-Limit Signalling** solution. Its `ai_integration` arm now has real consumers, since scope admits agents and skills. (in score)
19. **Unguided Change Construction** *(Endpoint Commands)* — assembling a proposal's `changes[]` demands prior knowledge of each command's shape, so the shape gets discovered by refused round-trips inside gated writes; promoted from Later, where it had been deferred precisely because `changes[]` ships as pass-through — the pass-through is what makes it bite. The contract refresh now publishes the change types and the nested-only rule, so what remains unpublished is narrower than it was. Relates to *Proposal Write-Flow*.
20. **Success Reported for a Dead Proposal** *(Endpoint Commands)* — a created proposal is reported as a success while the server has already invalidated it, so a human confirms a gated write that produced an object nothing can move forward; the sharpest available violation of failing legibly, and its candidate asks the server rather than judging validity locally.
21. **Change Targets Unidentifiable from the CLI** *(Endpoint Commands)* — a change names an existing element by a legacy numeric identifier the operator had to read off a web-UI URL mid-write, which is what falsified VISION success #2's *without the human needing any knowledge of the API*. The contract refresh resolves this for roles through a declared transition-only read parameter; accountabilities and domains still carry no readable number. Relates to *Governance Reads*, where the identifier now surfaces.
22. **Proposal Circle Not Choosable** *(Endpoint Commands)* — a proposal has no circle of its own and lands in the circle of its anchor tension's sensing role, so a change to a circle's own governance has to be routed through the parent circle; the routing has to be established before a change set can be assembled, so it clusters with *Unguided Change Construction*.
23. **Tension Details Rejected at Capture** *(Endpoint Commands)* — supplying a tension's agenda label or meeting type at capture is refused with a message naming a rule that doesn't apply, on a feature that has otherwise landed; the contract refresh leaves tension creation untouched, confirming this was not fixed upstream. Clusters with *Tension Capture*.
24. **Proposals Touching My Roles Unfindable** *(Endpoint Commands)* — proposals cannot be filtered by what their changes affect, so finding which ones bear on the roles the operator fills means reading every proposal's change set; clusters with the write-path fidelity problems above it, and it is the find step the impact-review path rests on. Relates to *Self-Service Reads*.
25. **Focus and Election Invisible** *(Endpoint Commands)* — the operator cannot see which focus a filler holds or whether they were elected and until when; a divergence rather than a missing feature, since the API serves this and the CLI's own closed include set is what refuses it. Clusters with *Actors Disconnected from Governance*.

## Next

A maintainability refactor of the settings layer, the read-surface work that has landed, the agent operating surface being picked up again, the drift check the contract refresh argued for, two write-path problems whose shape is still open, and the first of the newly-admitted scope areas.

- **Duplicated Setting Resolution** *(Client Foundation)* — collapse the per-setting flag→env→.glassfrogrc→default chain into one composable resolver before more settings copy the seam; the call-site retrofit has landed, with the composable source resolution following. Relates to *Undefined Connection Settings* and *Unconsumable Output*, whose landed call sites it retrofits. (in score)
- **Undiscoverable Governance** *(Endpoint Commands)* — cross-model search by topic/relevance over the record (roles, policies, role-fillers); extends the read surface beyond direct lookups and supports working a tension (relates to *Tension Capture*). (addressed)
- **Unequipped Agent Operators** *(Agent Operating Surface)* — the AI agent driving the CLI has no packaged operating knowledge, so it rediscovers how to operate the CLI each session and can mis-drive it or run ungated writes; strategically core to VISION success #2. The orientation knowledge, the write-safety guardrail, the operator paths, and the packaging have landed, and the surface is being picked up again. Relates to *Runtime-Dependent Distribution*. (in score)
- **Spec Drift Goes Unnoticed** *(Project Foundation)* — VISION success criterion #3 promises the drift is caught, and no capability implements it: the vendored contract fell behind the published one while neither the contract's version field nor the vendor's own changelog signalled it, and the cost landed as capabilities scoped against superseded facts. Real, but nothing in Now is blocked on it. Relates to *No Automated Pipeline*, where the check would ride.
- **Nothing Learned Is Kept** *(Agent Operating Surface)* — the operating surface discards what live payloads already taught it, so every session re-derives the same identifier resolutions and a target resolved earlier is declared unresolvable again; clusters with its parent above, and its candidate is where VISION Exclusion 4 has to be settled — now for the accountability and domain residue only, since the contract refresh answers the role case on a read. Relates to *Change Targets Unidentifiable from the CLI*.
- **Non-Governance Writes Ungated** *(Agent Operating Surface)* — the write-safety gate is scoped to the governance record by design, so a write surface that is not governance passes through without the confirmation every other write requires; the boundary can be stated before such a surface exists, which costs less than discovering the gap once it does. Relates to *Organizational Conversation Out of Reach*.
- **Lagging Counts Read as No Response** *(Endpoint Commands)* — a proposal's response summary lags the operator's own recorded response, so unchanged counts read as nobody having answered; documentation-shaped, and already settled in practice by the refusal of a second response, which is why it follows the sharper reporting problem in Now.
- **Oversized Content Unsignalled** *(Client Foundation)* — the server reports when a saved record's content is too large to read back in one response and nothing surfaces that report, so a caller cannot tell what it read is incomplete; narrower than the Now items and not yet met in practice. Relates to *Silent Truncation*.
- **Role Filling Requires Assembly** *(Endpoint Commands)* — everything needed to fill a role is spread across separate reads the caller must stitch together; the most immediately useful of the newly-admitted scope areas, being a plain read with no feature gate that replaces many calls with one. Relates to *Governance Reads* and *Self-Service Reads*.

## Later

The narrowest write-path gap, a Maintainer-facing review-quality enhancement, and the newly-admitted scope areas whose need is gated or anticipated rather than felt.

- **No Way to Discard a Dead Draft** *(Endpoint Commands)* — an invalidated draft carries no available transitions and the CLI offers no way to remove it, so clearing it means leaving the command line for the web UI; narrowest of the write-path problems in scope (it affects the Practitioner alone), with a web-UI workaround, and possibly documentation only if the API carries no delete.
- **Shallow AI Reviews** *(Project Foundation)* — better-grounded Copilot PR reviews via a configured environment; a Maintainer-facing enhancement that pairs with the pipeline work.
- **Agent Capability Unverifiable** *(Endpoint Commands)* — when an AI agent fills a role, nothing shows which skills it holds or which the role expects; newly admitted to scope, and gated behind `ai_integration`, so the organization must enable the flag before it is even exercisable. Relates to *An Actor's Governance Footprint*.
- **Organizational Conversation Out of Reach** *(Endpoint Commands)* — discussion bearing on governance work happens in channels the CLI can neither read nor write; newly admitted to scope, and recorded as anticipated rather than felt, since the API exposes this surface ahead of the web app.
