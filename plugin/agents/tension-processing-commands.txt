# Composed-leaf registry — the tension commands the Tension Processing Path
# composes (066 Tension Processing Path).
#
# THE single source of "which glassfrog tension leaves the processor composes",
# consumed by BOTH:
#   - the tension-processor agent  (plugin/agents/tension-processor.md)
#     — its "Composed commands" section names exactly these leaves and no others
#   - the drift guard              (internal/build/tension_processing_guard_test.go)
#     — it checks every leaf here still resolves to a `tension` subcommand in the
#       shipped CLI, AND that no leaf here appears in 063's gated proposal-write
#       registry (plugin/hooks/gated-commands.txt) — the ungated-writes invariant
# so the artifact prose and the guard can never disagree about the composed
# surface (plan ADR-5, mirroring 063's gated-commands.txt and 064's
# composed-reads.txt).
#
# Each non-comment, non-blank line is ONE `glassfrog tension` leaf the processor
# may invoke, written as the two-token `tension <sub>` pair (matching how 063's
# registry writes its `proposal <sub>` leaves, so the disjointness check compares
# like with like). Three are situating reads (list, get, subroles); three are the
# operational writes 063 leaves ungated by design (create, update, discard). No
# `proposal` leaf ever appears here — the path never crosses into a governance
# write (spec non-behavior; ADR-3).
#
# Renaming or dropping one of these commands in the CLI — or pulling one into
# 063's gated set — turns the drift guard red; the artifacts cannot silently
# name a command the CLI lacks or a write the guardrail gates.
tension list
tension get
tension subroles
tension create
tension update
tension discard
