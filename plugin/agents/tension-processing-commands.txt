# Composed-leaf registry — the tension commands the Tension Processing Path
# composes.
#
# THE single source of "which glassfrog tension leaves the processor composes",
# consumed by:
#   - the tension-processor agent  (plugin/agents/tension-processor.md)
#     — its "Composed commands" section names exactly these leaves and no others
# so the artifact prose and this registry can never disagree about the composed
# surface (mirroring the write-safety gate's gated-commands.txt,
# plugin/hooks/gated-commands.txt, and the sibling composed-leaf registries in
# plugin/agents/).
#
# Each non-comment, non-blank line is ONE `glassfrog tension` leaf the processor
# may invoke, written as the two-token `tension <sub>` pair (matching how the
# write-safety gate's registry writes its `proposal <sub>` leaves, so the two
# read like with like). Three are situating reads (list, get, subroles); three
# are the operational writes the write-safety gate leaves ungated by design
# (create, update, discard). No `proposal` leaf ever appears here — the path
# never crosses into a governance write.
#
# The ungated posture this registry promises holds only while no leaf here
# appears in the write-safety gate's registry (plugin/hooks/gated-commands.txt)
# — so a rename or drop in the CLI, or an edit to either registry's membership,
# means revisiting both files and the agent artifact together; the artifacts
# must never name a command the CLI lacks or a write the guardrail gates.
