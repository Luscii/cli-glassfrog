# Composed-leaf registry — the commands the Proposal Drafting Path composes.
#
# THE single source of "which glassfrog leaves the drafter composes", consumed by:
#   - the proposal-drafter agent  (plugin/agents/proposal-drafter.md)
#     — its "Composed commands" section names exactly these leaves and no others
# so the artifact prose and this registry can never disagree about the composed
# surface or its gate posture (mirroring the write-safety gate's
# gated-commands.txt, plugin/hooks/gated-commands.txt, and the sibling
# composed-leaf registries in plugin/agents/).
#
# Each non-comment, non-blank line is ONE `glassfrog` leaf the drafter may
# invoke, written as the two-token `<group> <sub>` pair — or a single token for
# a top-level command (matching the token grammar of the sibling registries, so
# they read like with like). Three are situating/grounding reads (tension get,
# proposal list, proposal get); one is the single governance write the
# write-safety gate confirms by design (proposal create), run only through the
# confirmed write flow; three are routing reads (me roles, tension list, roles
# — see the annotated block below); one is the consultation read (proposal
# grammar — see its annotated line below). No other proposal write ever appears
# here — the path never advances, responds to, or withdraws a proposal (that is
# the proposal-circulation and proposal-impact-review paths).
#
# The gate posture this registry promises holds only while `proposal create` is
# listed in the write-safety gate's registry (plugin/hooks/gated-commands.txt)
# and the situating reads are absent from it — so a rename or drop in the CLI,
# or an edit to either registry's membership, means revisiting both files and
# the agent artifact together; the artifacts must never name a command the CLI
# lacks or a write the guardrail stops confirming.
tension get
proposal list
proposal get
proposal create

# Routing reads. The three reads below are the named reads of the circle-routing
# rule record's procedure
# (plugin/skills/proposal-drafting/references/circle-routing-rule.md). They are
# the routing step's reads: the drafting workflow's first step consults that
# record and runs these reads in the record's order to determine the target
# circle and every eligible anchor before an anchor is settled on. The path
# names the record and runs its reads; it never restates the record's rule.
me roles
tension list
roles

# Consultation read. The read below renders the change-set grammar reference —
# client-less and credential-free, so it never prompts — and the workflow's
# consult step reads it once per delegation, before assembly. A failed read is
# noted in the returned record and never withholds the draft. The rendering is
# consulted, never restated: no change type or recorded shape is copied into
# the drafting surface.
proposal grammar
